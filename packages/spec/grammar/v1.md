# DSL 1.0.3 — grammar notes

Normative: [`v1.ebnf`](v1.ebnf). This page maps every construct in `skills/markdown-ui-dsl/SKILL.md` to its production
and records what the grammar had to decide. Constructs are traced by hand against all seven `examples/*.ui.md`.

## Construct → production

| SKILL.md construct | Production |
| --- | --- |
| `||| COLUMN |||` / `=== ROW ===` | `column`, `row` |
| `::: CARD / MODAL / HEADER / FOOTER :::`, `::: BUBBLE USER/AGENT :::` | `card`, `modal`, `header`, `footer`, `bubble` |
| `--- END ---` | `end_marker` (closes the innermost open block) |
| `***` divider | `divider` |
| `> hint`, `> @sm token: value` | `hint`, `responsive_directive` |
| `<!-- comment -->` | `comment` |
| headings, `**bold**` | `heading`, `emphasis` |
| `[ Text ](action)` | `button` |
| `|[ Active ]| B | C |` | `tabs_line` |
| `[ text: … ]`, `[ IMG: … ]`, `(( Tag ))` | `text_input`, `image`, `badge` |
| `[ ]`/`[x]`, `( )`/`(x)`, `[on]`/`[off]` | `checkbox`, `radio`, `toggle` |
| `[v] Sel {a, b}` / `{dynamic: x}` | `dropdown`, `options` |
| bullet / numbered lists, nested layout in an item | `list`, `list_item` |
| Markdown tables | `table` |
| YAML frontmatter | `frontmatter` |

## Decisions and ambiguities handed to T-011

| ID | Ambiguity | Provisional behaviour (until ADR in T-011) |
| --- | --- | --- |
| A-01 | `[ Text ](x)` is both button and link shape | Treated as **button**; `[Text](x)` with no inner spaces is a **link**. |
| A-02 | Bare `[ Text ]` with no `(action)` | Button without action. Collides with `[ text: … ]`/`[ IMG: … ]` — the typed prefixes win. |
| A-03 | `---` role: frontmatter fence, table separator cell, and (forbidden by SKILL.md) divider | Only the first line of the file is a frontmatter fence; elsewhere `---` is never a divider. Inside a table it is a separator cell. |
| A-04 | `--- END ---` vs `---`  | `--- END ---` exact-match line only. |
| A-05 | `|[ A ]| B |` tabs vs table row | `|[` opener ⇒ tabs line; otherwise a table needs a separator row. |
| A-06 | `[x]` (checkbox) vs button `[ x ]` | `[x]` with no spaces and a following label ⇒ checkbox; with spaces ⇒ button. |
| A-07 | `*` as bullet vs emphasis | `* ` (star + space) at line start ⇒ bullet. |
| A-08 | Escaping | Undefined in 1.0.3. T-011 fixes the escape set (`\[`, `\]`, `\|`, `\{`, `\}`, `\\`) and literal contexts (code spans/fences). |
| A-09 | Nesting where a closer is missing | 1.0.3 relies on balance; the parser reports `unclosed` at the opener and recovers at EOF (4 of the original examples were unbalanced — see B-01). |
| A-10 | Hint scope | A hint attaches to the nearest enclosing block above it (SKILL.md); the parser records position and parent, the meaning stays natural-language. |
| A-11 | Unknown breakpoint token (`@xs`) | Plain hint, with warning. |
| A-12 | Comments inside code fences | Literal (fence wins). |

Hand-trace status: all seven examples tokenise into these productions with no leftover lines once A-01…A-07 are applied.
